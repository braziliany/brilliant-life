# 璀璨人生 v1.4 Sprint 1：page.tsx 拆分实施计划

## Sprint 目标

在不改变产品行为的前提下，将当前约 1,006 行的 app/page.tsx 拆成按页面区域组织的 React 组件，降低单文件维护风险，为后续领域逻辑拆分建立边界。

核心策略：

> 只搬 JSX，不重写业务。

- 所有 useState、useEffect、fetch、保存、删除和导出函数继续保留在 app/page.tsx；
- 日期、节假日、工资和健康统计继续在 app/page.tsx 计算；
- 新组件只通过 props 接收数据和回调；
- 现有 DOM 顺序、className、文案和 ARIA 属性保持不变；
- app/globals.css 必须保持字节级不变；
- 建议周期为 5 个工作日，每一步独立提交、独立验收、可以单独回滚。

## 1. 范围约束

### 允许修改

- app/page.tsx
- app/page-view.types.ts
- app/components/shell/*.tsx
- app/components/home/*.tsx
- app/features/health/*.tsx

- app/features/salary/*.tsx
- 本 Sprint 计划与开发记录文档

page-view.types.ts 只能包含 TypeScript 类型，不允许加入业务函数、常量或副作用。

### 禁止修改

- app/globals.css
- app/layout.tsx
- app/pwa-registration.tsx
- app/api/**
- db/**
- drizzle/**
- worker/**
- public/**
- scripts/**
- package.json 和 package-lock.json
- vite.config.ts、next.config.ts 和 .openai/**

### 明确不做

- 不修改数据库 schema、迁移或 D1 数据；
- 不新增、删除或调整 API；
- 不修改 API URL、HTTP 方法、请求体和响应体；
- 不修改 UI 布局、颜色、字号、间距、尺寸、动画和文案；
- 不引入 Context、Redux、Zustand或任何新依赖；
- 不优化业务算法；
- 不拆分 CSS；
- 不顺手修复无关问题。

## 7. 风险控制

| 风险 | 控制措施 |
|---|---|
| props 遗漏 | 每次只拆一个区域，依赖 TypeScript 检查 |
| 按钮无反应 | 不改事件函数，逐按钮验收 |
| DOM 顺序变化 | 原样迁移 JSX，禁止改 CSS |
| className 丢失 | 截图与 DOM 对比 |
| 重复请求 | 所有 fetch 保留在 page.tsx |
| 闭包状态变化 | 回调函数保留在父组件 |
| 一次改动过大 | 七个独立 commit，逐步回滚 |
| 顺手优化导致行为变化 | 文件白名单和禁止事项 |
| props 数量较多 | 可使用区域 ViewModel 类型，但不引入 Context |

## 8. Definition of Done

只有全部满足才完成 Sprint：

1. page.tsx 的主要 JSX 已拆成独立组件；
2. 数据库、迁移、API、CSS、依赖均无修改；
3. 桌面端和手机端 UI 与拆分前一致；
4. 所有交互行为一致；
5. 网络请求契约一致；
6. 所有计算结果一致；
7. 构建和原测试通过；
8. 子组件没有 fetch、数据库访问或业务算法副本；
9. 每一步都有独立提交和验收记录；
10. 可以逐 commit 回退，不需要数据库回滚。

Sprint 1 的价值不是追求指定行数，而是安全建立视图边界。完成后，下一 Sprint 才讨论领域逻辑、hooks 或 API client 的拆分。
