# Calendar

Calendar 分别保存三种事实：

- 官方日历：年份化配置描述法定休假、官方调休上班和星期规则。未配置年份明确标记未知，不改写既有年度数据。
- 个人安排：`calendar_overrides.is_workday` 保留原布尔格式，`true` 表示安排上班，`false` 表示安排休息；没有该日期行表示跟随官方。历史覆盖保持原值，不推断为出勤或工时。
- 实际工作：`calendar_work_records` 按上海自然日的日期键保存 `worked`、nullable `hours` 和更新时间。`worked=true` 是已确认上班，允许工时未知或明确的正数（最多 24 小时），例如早班 8 小时；`worked=false` 是已确认未上班，小时数可未知或明确为 0。没有行表示未记录实际情况，绝不等同于 0 小时。小时数与是否上班分别保存，拒绝“上班且 0 小时”或“未上班且正工时”的矛盾输入。

日期最终工作状态的优先级为：实际记录 → 个人安排 → 官方法定休假/调休 → 普通周一至周五/周末。实际记录可用于所有日期类别，不受官方休息状态阻止。官方状态和个人安排仍单独显示，即使与实际情况不一致。

工作日计数继续按最终状态计天：实际上班一天计一个工作日，8 小时不会被折算成某个标准班长的比例；未记录实际情况时沿用个人安排/官方状态。月历、月度进度、全年配置、Annual 和 Widget 使用同一解析；Life Insights 使用相同的最终工作日分组。Annual 的历史字段名 `actualWorkdays` 保持兼容，其含义仍是最终日历工作日数，并不表示每一天都有实际出勤凭据。

新增的工时汇总仅累加明确填写的小时数，同时报告实际记录天数和工时未知天数；无记录与全部工时未知显示“暂无”，明确填写 0 显示 0。输入仍允许任意合法小数精度（`step="any"`）；总量展示通过统一 `formatRecordedHours` 对各原始数值的规范十进制表达求和，避免 `0.1 + 0.2` 的浮点尾差，不设置新的小数位限制，不改写原始记录或数值统计。不存在标准班长、自动加班、小时工资或备注转工时规则。Salary 仍只消费最终工作日数量；改变小时数本身不会改变按日计算的工资，已保存工资快照不自动重算。详见 [Salary](./Salary.md)。

日期编辑保留原入口，点击日期后分别保存“我的安排”和“实际上班”。“我的安排”使用上班、休息、默认三选项，分别对应原安排上班、安排休息、恢复默认；“实际上班”保留出勤状态和以小时为单位的工作时长。请假及其他安排没有明确的结构化业务契约，仍只作为月度文本备注，不提供虚假状态选项。恢复单日或整月默认只清除个人安排，保留实际记录；若要完全回到官方状态，还需主动清除该日实际记录。

同一日期的两个表单分别维护草稿、保存中、成功和失败状态；保存一项只同步该项。服务端重新读取时，未编辑表单跟随更新，脏草稿保留并提示冲突，用户可以主动采用服务器数据。切换日期或月份会结束原日期编辑，不把原日期草稿提交到新日期。

全年读取按年份分别缓存经过响应校验的结果。加载中和失败均有独立状态：没有该年缓存时不展示默认统计；已有缓存时保留并明确提示可能未更新。失败可重试，旧请求不能覆盖后来选中的年份；工作日计算规则保持不变。

## 持久化与兼容

- `GET /api/calendar?month=YYYY-MM` 或 `?year=YYYY` 返回原 `overrides` 数组及新增 `workRecords` 数组；按同一半开日期区间读取，支持跨月、跨年。
- 原 `PUT /api/calendar` 和 `DELETE /api/calendar` 保持布尔覆盖与单日/整月清除契约。个人安排与实际记录共用 UTC 日期往返校验，拒绝不存在的日期并保留合法闰日；错误 JSON、无效输入与非法日期均在写入前返回 400，不改变合法历史格式。
- `PUT /api/calendar-work` 完整替换 `{date, worked, hours}`；省略或显式 null 的 `hours` 表示未知，不表示 0。`DELETE /api/calendar-work` 只接收 `{date}` 并清除实际记录。写入要求 Owner 访问、同源 Origin 和 JSON；非法日期、未知字段、矛盾工时均在写库前拒绝。
- `0015_romantic_bastion.sql` 只新增实际工作表，不回填、不更新旧覆盖、备注、工资或其他历史事实。生产结构升级需批准、备份及隔离恢复验证，先迁移后发布 Worker，不重放已应用迁移；本次生产执行结果见[本月开发记录](../04-开发记录/2026-10.md)，顺序及失败处理见[部署与恢复手册](../03-运维/部署与恢复手册.md)。
- 旧布尔覆盖可无歧义地显示为“安排上班/安排休息”，无法从中推断实际工时，因此不做这种转换。月度备注仍为原文本，不解析或迁移。

当前年度 Annual 的跨领域事实视图继续服从 `asOf`；全年日历配置另行展示，并明确标记未来日期。

## Calendar Widget Current Truth

- Phase 1 只读端点为 `GET /api/v1/calendar/widget`，只允许上海时区当前月份及相邻月份。
- Widget 直接复用 Calendar domain 的日期解析、官方节假日配置、个人安排和实际记录；不维护第二份节假日或工作日真相源。
- 返回范围只包含月度最终日期状态、官方事实、个人安排标记和备注存在性摘要，不返回备注正文、其他生活领域或内部记录标识。
- Widget 不提供 mutation endpoint；POST、PUT、PATCH、DELETE 均拒绝，Widget 自身无 D1 写入；实际工时由 Owner 日期编辑 API 保存。
- Widget 使用独立、path-scoped 的 Cloudflare Access Application 与 Calendar Service Token；该 token 不能进入 Health Ingest、Dashboard 或其他 private read 路由。
