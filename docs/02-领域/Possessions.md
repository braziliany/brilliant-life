# 物品档案

## 定位与边界

记录拥有什么、何时购买、实际记录过多少次使用，以及物品后来如何退出持有。Phase 1（含 1.1 视觉与 1.2 保存修复）已正式上线，入口 `/possessions`，继续由 Owner Access 保护。生产只读空数据与用户 iPhone 视觉已确认；生产写入及 iPhone 实际保存尚未独立验收，具体发布证据见当月记录。

本领域不是消费评价、估值或账本。Life Finance 仍是资金流水事实来源，不从钱迹生成物品，不自动对账或关联 dormant `asset_id`，不合计 Salary，不改变 Finance、Salary、Calendar、Annual 或 Insights 的算法。物品价格是用户独立填写的成交事实，不冒充第二份财务流水。

参考[物念公开介绍](https://huanxi.pub/home/)中的物品、使用记录与愿望清单流程，独立实现数据结构与 Pulse 页面；不使用其源码、图片、品牌、UI、评分、AI 建议或提醒。

## 持久化事实

| 表 | 内容与约束 |
|---|---|
| `possession_items` | 数值主键；名称、自由文本分类、可空品牌型号/购买日/成交分金额、备注、状态、可空结束日期与归档时间、可空愿望来源、创建/更新时间 |
| `possession_uses` | 数值主键；有效物品外键、使用自然日、正整数次数、备注、创建/更新时间；不存冗余累计次数 |
| `possession_wishes` | 数值主键；名称、可空预算分金额/计划日期、备注、状态、创建/更新时间 |

- 单人 Owner 档案，不新增共享、多租户或权限系统。复用 Dashboard Access，机器入口凭据没有新增用途。
- 使用记录到物品、物品到来源愿望均为 `ON DELETE RESTRICT` 外键，禁止孤儿和意外级联删除。一个愿望最多转成一件物品（唯一 `source_wish_id`）。
- 物品提供创建、读取、完整编辑、归档/取消归档；不提供永久删除 API。归档只收起列表内容，不修改当前状态、不代表结束持有、不清除使用历史。误录的使用记录可独立删除。
- 当前状态：`in_use` 使用中、`idle` 闲置、`sold` 已出售、`gifted` 已转赠、`retired` 已淘汰。后三者必须显式填写真实 `ended_date`；有购买日时结束日不得早于购买日。不用更新时间猜退出日期。纠正为持有状态时清除结束日。
- 金额为 CNY 整数分或 NULL。缺失价格/预算不等于零；明确零元合法。不采用折旧、残值、出售收入抵扣或汇率。前端元输入最多两位小数，以十进制整数换算为分，不经过浮点乘法；服务端要求非负安全整数分。
- 日期为真实的 `YYYY-MM-DD`，共享既有 UTC 往返校验，统计截止日由服务端按上海时区生成。实际购买、停止持有与使用不接受未来日期；愿望计划日期允许未来。
- 使用记录次数默认 1，每条范围为 1–1,000,000 的整数（输入防错上限）；同一天可有多条真实记录，不以日期去重，也不推断未记录日期。允许补录历史使用，使用事实日期不强制等同于持有期间。

## 派生计算

- 累计记录次数 = 截止日及之前的实际使用记录次数之和；修改、删除后重新派生，物品表没有缓存总数。列表使用 SQL SUM，详情由同一批记录计算，两者接受相同截止日。
- 每次使用成本 = 已知成交价 ÷ 累计记录次数。购买日缺失不阻止此项计算；价格未知或没有有效分母时为“不可计算”。显示明确注明“按已记录次数”，不声称已记录全部真实使用。
- 持有天数采用自然日含首尾口径：购买当日为第 1 天，按 UTC 日期相减再加 1，不受宿主机时区或夏令时影响。仍持有时截止至统计日；已退出时截止至结束日和统计日中的较早者。购买日未知、结束日未知或截止日早于购买日不可计算，不生成默认购买日。
- 每天持有成本 = 已知成交价 ÷ 有效持有天数。无需使用次数；价格或持有天数缺失不可计算。明确零元在分母有效时结果为零。
- 成本只在展示时按元保留两位小数，不写回价格、不存储成本指标，不进行价值评分或排名。

## 愿望转入

状态为 `wanted` 想买、`purchased` 已购买、`cancelled` 取消。取消保留愿望记录。已购买不会自动生成物品，须主动选择“转入档案”，重新确认名称/分类等实际信息。转入表单可以带入名称与备注，**不带入预算或计划日期作为成交价/购买日期**，这些字段默认未知。

转换使用单条条件 INSERT SELECT，并由来源唯一约束兜底；并发或重复转换只能创建一次，之后返回 409。来源愿望保留，已转入的愿望不能改回想买或取消，但仍可纠正其名称、备注和预算。物品后续编辑不改写来源。

## API 契约

所有响应 `Cache-Control: no-store`。非本地环境继续依赖既有 Owner Access 边界及已关闭的 Worker 公共入口；没有新增绕过路径。写入必须为受支持方法、同源 Origin、`application/json`，未知字段和非法输入在访问数据库前拒绝。

| 入口 | 方法与用途 |
|---|---|
| `/api/possessions` | GET 总览；GET `?itemId=正整数` 读取详情及使用记录 |
| `/api/possessions/items` | POST 新增；PUT `{id,...完整物品字段}`；PATCH `{id,archived:boolean}` |
| `/api/possessions/wishes` | POST 新增；PUT `{id,...完整愿望字段}` |
| `/api/possessions/uses` | POST 新增；PUT `{id,itemId,usedOn,count,note}`；DELETE `{id,itemId}` |
| `/api/possessions/convert` | POST `{wishId,item:{完整物品字段}}`，保留来源且实际价格可空 |

PUT 是完整替换可编辑字段，创建时间、来源关系和归档状态不由 PUT 覆盖。使用记录修改/删除同时匹配记录 ID 与物品 ID，不能把他件物品的记录移过来。成功新增为 201、读取/更新/归档/删除为 200；非法输入 400、未认证 401、非法 Origin 403、缺失实体 404、方法不支持 405、转入/状态冲突 409、非 JSON 415、存储失败 500。错误不回传内部 SQL 或路径。

Phase 1.2 客户端用 `itemPayload`、`wishPayload`、`usePayload` 明确投影可写字段，草稿初始化与提交都经过投影，不直接展开 GET/read model。物品只写名称、分类、品牌型号、购买日期、成交分金额、备注、状态和结束日期；愿望只写名称、预算、计划日、备注和状态；使用只写受服务端校验的 `itemId`、使用日期、次数和备注。编辑目标 `id` 由页面单独追加，不在表单中编辑。时间戳、归档时间、愿望来源和派生 metrics 均不进入普通编辑请求，服务端未知字段拒绝规则保持不变。

迁移 `0016_possessions_phase1.sql` 只新增上述三表、必要约束与日期索引。旧九张表不变，无回填、跨域外键、重算或历史迁移。购买日、退出日与使用日分别索引，保留未来按年读取新增、退出和使用事实的能力；Annual 本轮不增加区块，Insights 不接入此领域。

## 页面与验收

桌面导航新增“物品”，首页 Hero 下方保留一张移动端可见的完整物品入口卡片，遵循现有移动端隐藏全局导航的规则。入口只介绍现有能力，不新增首页统计请求或虚构数字。独立深色页展示简洁总览、物品/愿望/归档视图，不把全部字段堆到首页。无足量真实数据，不新增图表或依赖。

Phase 1.1 详情采用桌面横向主视觉：左侧名称、分类/状态、品牌和简短描述，右侧展示已保存价格和既有派生指标；物品信息与每天成本组成次级两栏，使用记录为紧凑横向行。手机按标题、关键指标、集中操作、次级信息和记录顺序重排。计算口径和完整长备注可展开，未知值与不可计算仍明确显示；编辑、使用和归档回调保持，表单未缩小或更改字段绑定。

表单只在保存成功后关闭；失败保留草稿并显示错误。读取失败没有可用数据时显示失败和重试，存在缓存时明确内容可能过期；请求取消保护不同详情切换。生产鉴权不以 mock、组件截图或本地 D1 成功冒充通过。设备验收与本轮实际门禁结果见[当月记录](../04-开发记录/2026-10.md)。
