# 璀璨人生 v1.4 Sprint 5：职业经历领域逻辑收敛实施计划

## 1. Sprint 目标

在不改变任何用户可见行为的前提下，将职业经历相关的确定性计算从 `app/page.tsx` 收敛到独立领域模块，并建立回归测试。

本 Sprint 是 v1.4.0 领域逻辑收敛阶段的最后一项：Sprint 2 已处理健康领域，Sprint 3 已处理工作日历领域，Sprint 4 已处理工资领域。本次只完成职业经历领域中确实存在的纯逻辑，不扩张模块边界。

> 核心原则：只移动已有纯计算，不移动状态、副作用、网络请求、表单交互、确认弹窗或数据库规则。

- 新增 `tests/career-domain.test.mjs`，8 项职业领域测试全部通过；

- 新增、编辑、删除、展开、确认、状态和错误处理流程保持原位；
- UI、CSS、API、D1、schema、迁移、请求格式和依赖均未修改；
- API 6/6、Health 7/7、Calendar 11/11、Salary 6/6、Career 8/8 及生产构建全部通过；
- `rendered-html` 在普通 Node 环境中仍受既有 `cloudflare:` ESM 协议限制，本 Sprint 未越权修改该测试，发布后通过 Worker HTTP 响应验证页面渲染。

## 3. 当前行为基线

实施前必须锁定以下现状：

1. 经历按 `startDate` 升序排列；
2. 开始年月相同时按 `id` 升序排列；
3. 新增经历后加入列表并重新排序；
4. 编辑经历时按 `id` 替换原记录并重新排序；
5. 删除经历时只移除目标 `id`；
6. 新增表单草稿为：单位、职位、开始年月和工作内容为空，结束年月为 `null`；
7. 编辑表单草稿完整复制当前记录，但不包含 `id`；
8. 任职时长按包含首尾月份的方式计算；
9. 未填写结束年月时，以当前上海年月为计算终点；
10. 小于一个完整显示月的兜底文案仍为“不足 1 个月”；
11. 原数组和原记录不能被纯函数修改。

这些规则是回归基线，不代表本 Sprint 有权重新设计它们。

## 4. 计划提取的纯函数

### 4.1 `createEmptyWorkExperienceDraft`

返回与当前新增表单完全相同的空草稿：

```ts
createEmptyWorkExperienceDraft(): WorkExperienceDraft
```

用途：消除页面初始化和打开新增表单时的重复对象字面量。

### 4.2 `toWorkExperienceDraft`

从已有经历生成编辑草稿：

```ts
toWorkExperienceDraft(experience: WorkExperience): WorkExperienceDraft
```

要求：

- 完整保留五个可编辑字段；
- 不携带 `id`；
- 不修剪或改写字段；
- 不修改传入记录。

### 4.3 `sortWorkExperiences`

按当前页面规则返回新数组：

```ts
sortWorkExperiences(experiences: WorkExperience[]): WorkExperience[]
```

排序规则必须保持为：

1. `startDate.localeCompare` 升序；
2. 同年月按 `id` 升序。

不得改变原数组顺序。

### 4.4 `upsertWorkExperience`

统一新增和编辑成功后的列表计算：

```ts
upsertWorkExperience(
  experiences: WorkExperience[],
  experience: WorkExperience,
  editingId: number | null,
): WorkExperience[]
```

要求：

- `editingId` 为 `null` 时追加记录；
- 编辑时只替换响应记录对应的 `id`；
- 完成后沿用当前排序规则；
- 不修改原数组或其中记录。

### 4.5 `removeWorkExperience`

返回移除目标记录后的新数组：

```ts
removeWorkExperience(
  experiences: WorkExperience[],
  experienceId: number,
): WorkExperience[]
```

只按 `id` 过滤，不增加“找不到记录”等新错误行为。

### 4.6 `formatWorkExperienceDuration`

收敛当前任职时长计算：

```ts
formatWorkExperienceDuration(
  startDate: string,
  endDate: string | null,
  currentMonth: string,
): string
```

其中 `currentMonth` 使用页面已经确定的上海年月 `YYYY-MM`，领域函数本身不读取系统时间。

必须保留：

- 首尾月份均计入；
- `Math.max(0, ...)` 的现有负值保护；
- “X 年”“X 个月”“X 年 X 个月”的现有空格和中文格式；
- 零个月时的“不足 1 个月”。

不得新增日期格式校验或纠正非法区间。

## 10. 风险点与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 排序方向被误改 | 时间线顺序反转 | 固定升序样本和同月 `id` 回归断言 |
| 原地 `sort` 修改 React 状态 | 隐蔽状态污染 | 领域函数先复制数组并测试不可变性 |
| 编辑后未重新排序 | 修改开始年月后位置错误 | 编辑用例同时改变开始年月 |
| “至今”时长随测试日期漂移 | 测试不稳定 | 显式传入上海当前年月 |
| 持续时间边界被重新解释 | 用户看到不同年／月 | 锁定首尾月份均计入的现有公式 |
| 顺手统一前后端校验 | API 行为变化 | 服务端 `readExperience` 完全冻结 |
| 为职业模块增加无需求功能 | 范围膨胀 | 禁止重叠检测、空档分析、统计和新 UI |

## 12. Sprint 结束后的决策门

Sprint 5 完成后，不应自动继续拆分低复杂度模块。下一步先复核 v1.4.0 的完成程度：

- 若 `page.tsx` 仍主要承担大量可复用副作用，再单独规划 API client 与统一错误模型；
- 若当前维护成本已明显下降，则停止结构重构，进入 v1.4.1“数据可信”；
- 样式作用域迁移只有在存在真实冲突时才立项，不为追求目录整齐改写稳定 CSS；
- 不新增职业统计、空档分析或年度报告，除非出现明确使用需求和可靠数据基础。

Sprint 5 的成功标准不是减少指定行数，而是以最小改动完成职业领域的可测试边界，并保持网站外观和行为完全不变。
