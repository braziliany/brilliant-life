# 璀璨人生 D1 备份恢复说明

## 1. 数据库身份

| 项目 | 值 |
|---|---|
| 数据库名称 | `pulse-health-dashboard-db` |
| database_id | 仅保存在私有运维记录或环境变量 `PULSE_PRODUCTION_D1_ID` 中 |
| Worker | `pulse-health-dashboard` |
| D1 binding | `DB` |

数据库 ID 不是密钥，但恢复前必须用它区分生产库与演练库。健康上传 API Key、Cloudflare 凭据和 Access 配置不得写入备份 metadata。

## 2. 创建备份

在项目根目录执行：

```powershell
npm run db:backup
```

输出结构：

```text
backups/
└─ YYYY-MM-DD/
   └─ YYYYMMDD-HHmmss/
      ├─ database.sql
      └─ metadata.json
```

`metadata.json` 包含：

- 源数据库名称、ID、创建时间和 D1 文件大小；
- Worker 名称及当前版本；
- SQL 文件大小和 SHA256；
- 全部业务表的建表语句与行数；
- 唯一索引；
- 2026-07 工资快照、最新健康日期和职业经历顺序等恢复校验点。

`backups/` 已被 Git 忽略。至少保留最近 3 份月度备份、每次结构变更前备份和一份加密异地副本。

## 3. 验证备份或恢复库

```powershell
npm run db:verify -- `
  -Database "pulse-health-dashboard-recovery-drill-YYYYMMDD" `
  -MetadataFile "backups\YYYY-MM-DD\YYYYMMDD-HHmmss\metadata.json"
```

验证器会比较：

- 业务表清单；
- 唯一索引名称和 SQL；
- 各表行数；
- 7 月工资历史快照；
- 最新健康记录标识；
- 工作经历排序。

Cloudflare D1 远程查询禁止 `PRAGMA integrity_check`，会返回 `SQLITE_AUTH`。本项目不把该命令伪装成成功，而使用 schema、索引、行数和关键快照组合验证。

## 4. 非生产恢复演练

先创建独立测试库：

```powershell
npx wrangler d1 create pulse-health-dashboard-recovery-drill-YYYYMMDD --location apac
```

记录返回的 database_id，并与私有运维记录中的生产 ID 比对，确认两者不同。

执行恢复：

```powershell
npm run db:restore -- `
  -BackupFile "backups\YYYY-MM-DD\YYYYMMDD-HHmmss\database.sql" `
  -Database "pulse-health-dashboard-recovery-drill-YYYYMMDD" `
  -ConfirmRestore
```

恢复脚本会：

1. 验证 SQL 的 SHA256 与 metadata 一致；
2. 查询目标数据库真实 ID；
3. 拒绝默认恢复到生产库；
4. 先备份当前目标库；
5. 导入 SQL；
6. 自动运行一致性验证。

演练完成并记录结果后，确认名称和 ID，再删除临时库：

```powershell
npx wrangler d1 delete pulse-health-dashboard-recovery-drill-YYYYMMDD
```

## 5. 生产恢复

生产恢复属于高风险操作。优先使用 D1 Time Travel；使用 SQL 前必须先在独立测试库完成恢复演练。

脚本只有同时满足以下条件才允许生产恢复：

- 明确目标是生产数据库；
- 提供 `-ConfirmRestore`；
- 额外提供 `-AllowProductionRestore`；
- SQL 哈希与 metadata 一致；
- 自动创建恢复前安全备份。

不要把 `-AllowProductionRestore` 写入日常快捷命令。执行生产恢复前应停止编辑，记录当前 Worker 版本和 Time Travel bookmark，并再次核对数据库 ID。

## 6. Time Travel

查询当前信息：

```powershell
npx wrangler d1 time-travel info pulse-health-dashboard-db
```

Time Travel 会改变生产数据。恢复前仍须运行 `npm run db:backup`，并按 Cloudflare 当前保留期选择 bookmark 或时间戳。

## 7. 备份验收

一份可用备份必须同时满足：

- SQL 文件存在且非空；
- SHA256 与 metadata 一致；
- metadata 只记录目标数据库而非账户全部数据库；
- 六张业务表、索引和行数被记录；
- 已至少一次恢复到独立 D1 并通过自动验证。
