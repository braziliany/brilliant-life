# v1.5 数据中心信息架构与体验优化实施记录

## 1. 优化前主要问题

- 一级导航由健康、工作日历、每日目标、工作经历、工资五个工具入口组成，缺少“现在有哪些生活事实”的总览。
- 数据阅读按钮与 CSV、同步、编辑等管理操作视觉权重接近。
- 工作日历缺少本月已过、剩余工作日事实；职业区域的新增操作高于当前职业事实；工资缺少年内已保存快照累计。
- 数据中心与年度档案使用不同领域语言。

## 2. 新信息架构

数据中心现在采用：

```text
数据总览
├─ Health / 健康
├─ Time / 时间
├─ Career / 职业
└─ Finance / 财务（当前仅工资事实）
```

总览连接今日健康、本月时间、今年工资快照与当前/最近职业阶段，不增加 API 请求。

## 3. Tab / 领域变化

- 内部导航改为：总览、健康、时间、职业、财务。
- 保持 Sprint 10 的品牌-only 顶部，不恢复首页/数据中心大型导航。
- 移动端领域导航可横向滚动并保留键盘 focus 状态。

## 4. Health 优化

- 主卡改为“今日健康事实 / 健康趋势”，数据优先。
- 每日步数目标与体重趋势归入 Health 的“个人基线”，不再作为一级领域。
- CSV、同步状态与指南收进“工具”；趋势入口继续可直接访问。

## 5. Time 优化

- Calendar domain 新增纯汇总 `summarizeCalendarMonthProgress`，统一提供工作日总数、已过、剩余、法定假日、调休和个人调整。
- 月份与时间事实优先；全年配置、备注和日期编辑降级至“工具”。
- 过去月份剩余为 0、未来月份已过为 0；React 不复制工作日算法。

## 6. Career 优化

- Career domain 新增只读 `selectCurrentCareerStage`，优先当前在职记录，否则返回最近历史阶段。
- 当前/最近职位、公司、时间范围和任职时长置于时间轴之前。
- 新增、详情、编辑、删除全部保留，但不再成为首屏视觉中心。

## 7. Finance 优化

- 明确领域名称为 Finance，但页面内容仍限定为工资事实。
- Salary domain 新增 `summarizeSavedSalaryYear`，只累计 `salary_records` 快照的已保存月份、实发和个税。
- 当前月工资、年内累计、趋势和历史记录形成三层阅读顺序；不重算历史工资。

## 8. 每日目标处理

- 每日步数目标归入 Health / 个人基线。
- 调整目标能力完整保留。
- 未引入 Todo、GTD、打卡或提醒系统。

## 9. 响应式调整

- Desktop 总览为四列事实卡，平板与手机变为 2×2。
- Health 与目标在视觉顺序上相邻；手机端工具菜单使用底部宽面板，避免按钮挤压。
- Calendar 和工资累计在窄屏下自动降列，不通过无限缩小字体塞入内容。

## 10. 测试结果

- 新增数据中心 IA 契约测试 4 项。
- Calendar、Career、Salary 各新增 1 项纯领域回归测试。
- `npm run build`：通过。
- `npm run verify`：通过。
- `git diff --check`：通过。

## 11. 后续技术债

- 当前仍由单个 `page.tsx` 持有所有已加载状态；本轮没有增加请求或状态管理框架，后续只有在页面继续增长并出现真实维护成本时再拆分数据中心容器。
- `.annual-preview-state/` 是本地预览数据，不属于产品代码或本次交付。
