## 4. 领域函数设计

新增 `app/features/salary/domain.ts`。

### 4.1 calculateGrossSalary

输入工作日和完整政策所需字段，保持公式：

```text
工作日 × 日薪 + 额外收入 + 奖金
```

不对工作日进行新校验，不舍入。

### 4.2 calculateTaxableIncome

保持公式：

```text
max(0, 应发 − 固定扣除 − 请假扣款 − 起征点)
```

### 4.3 calculateIncomeTax

保持公式：

```text
计税收入 × 税率 ÷ 100
```

不主动保留两位小数，显示层继续负责格式化。

### 4.4 calculateNetSalary

保持公式：

```text
应发 − 固定扣除 − 请假扣款 − 个税
```

### 4.5 calculateSalarySummary

统一入口：

```ts
calculateSalarySummary(workdays, policy)
```

接收完整 `SalaryPolicy`，返回：

- `grossSalary`
- `taxableIncome`
- `incomeTax`
- `netSalary`

不得复制或覆盖政策字段，页面继续使用 API 返回的政策。

### 5.2 完整政策字段

### 5.3 税务边界

- 计税收入小于 0 时归零；
- 刚好达到起征边界时为 0；
- 超过边界时按政策税率计算。

### 5.4 零工作日与小数

- 保持零工作日当前结果；
- 保留 JavaScript 原始计算精度；
- 不在领域层添加 `toFixed` 或四舍五入。

### 5.5 前后端公式一致性

使用当前固定政策对 0、18、23、31 个工作日进行对照：

```text
salary domain 结果 === app/api/salary/policy.ts 结果
```

只读取后端纯函数进行测试，不修改 API 文件。

### 5.6 日历联动回归

使用 `countCalendarMonthWorkdays(2026, 6, {})` 得到 23 天，再验证完整工资结果，保护“日历 → 工作日 → 工资”链路。

## 9. 风险点

| 风险 | 控制措施 |
|---|---|
| 遗漏额外收入、奖金或请假扣款 | 完整政策字段测试 |
| 前后端算法漂移 | 多组工作日与 API 纯函数对照 |
| 新增舍入导致金额变化 | domain 禁止 `toFixed` 和主动舍入 |
| 保存与锁定范围扩大 | 明确留在 page.tsx 与 API |
| 工资 UI 或 CSV 变化 | 组件与导出函数冻结 |
| 日历联动变化 | 23 工作日跨领域回归 |
| 顺手修改政策 | API policy 和数据库冻结 |

只有工资公式完成纯函数收敛、全部冻结边界无差异、完整政策和日历联动测试通过、生产构建成功，Sprint 4 才算完成。
