# 物品档案本地验收

这是 Phase 1 独立本地验收环境，不是生产发布步骤。规则见[物品档案](../02-领域/Possessions.md)，本轮门禁见[开发记录](../04-开发记录/2026-10.md)。

## 启动

使用 Node 22，在项目根目录依次执行：

```powershell
npm run build
npm run preview:possessions:seed
npm run preview:possessions
```

`seed` 只在新隔离本地库创建结构及明确标注的合成数据。脚本没有 remote、reset 或任意路径入口；已有库会拒绝覆盖。状态保存于 Git 忽略的 `.wrangler/possessions-preview`，与既有预览数据和生产 D1 分离；绑定使用本地占位 ID，所有 D1 命令显式 `--local`。不要手工将真实备份导入此验收库。

`serve` 使用 Build 产物，监听 `0.0.0.0:4186`，调试端口 9286。若端口已有服务，应先确认占用进程，不结束未知进程。手机与 Windows 在同一局域网时，Safari 访问 `http://<Windows 局域网 IPv4>:4186/possessions`。本地使用项目既有开发主机认证规则，不修改 Access 或生产配置，不创建公网隧道。Windows 自己访问成功不能代替手机网络与 Safari 验收。

## 建议验收顺序

1. 从首页“物品”链接进入，查看合成耳机详情；购买信息、已记录次数和成本应一致，页面没有横向溢出。
2. 新建一件合成物品，价格和购买日期留空；保存后刷新，仍为未知，而非零元。再明确填写零元，确认展示和未知状态不同。
3. 添加实际使用，默认一次；补记历史日期，编辑次数，删除一条误录，确认累计数与每次成本随之重新计算。
4. 将状态改为已出售、已转赠或已淘汰，填写真实结束日期，确认持有天数停止在该日。归档/取消归档只改变列表显示，使用历史保留。
5. 进入愿望清单，编辑预算、计划日期及状态；已购买后显式转入。成交价和购买日期默认空，来源关系保留，重复转入不产生第二件物品。
6. 检查保存失败反馈与草稿保留（自动组件测试覆盖受控失败）；不要通过修改安全配置制造失败。生产 API 和生产数据不用于本轮验收。

本地组件浏览器测试与真实 Worker+D1 测试分别报告，不能写成生产 Access 或 iPhone 端到端已通过。用户确认本次实机验收通过后，立即停止此次预览进程并核实 4186 不再监听；不要停止其他项目服务。

## Phase 1.2 可重复保存链路

在 Node 22 下先 `npm run build`，再执行 `npm run test:possessions-worker`。该测试已纳入完整 `npm run verify`，使用已安装的 Playwright/Edge，无新组件库或浏览器依赖。它直接打开构建后的真实 `/possessions`，填写表单、发送 HTTP、调用 Worker API 写入本地 D1，随后刷新/重读，并以只读 SQLite 连接核对同一 D1 文件；不拦截 fetch，不使用模拟响应。

每轮使用新的 `.wrangler/possessions-phase12/worker-*` 本地库、占位数据库 ID、随机 loopback 端口和独立工具配置目录，显式 `--local`。它不读取或修改 `.wrangler/possessions-preview/state`，不占用或停止 4186；结束时只关闭自己的 Worker 和浏览器。`latest-worker.json` 指向最近一轮日志、实际请求字段、结果及七档截图。不要把这些测试改为 remote，或把真实数据导入其中。

覆盖物品新增/完整编辑/未知与零元、使用增改删/历史补录/归档保留、愿望编辑与显式转入、重复点击、真实 400/409 失败草稿恢复，以及 320/375/390/430/768/1024/1440px 的编辑、错误、详情和返回。已有组件受控响应测试继续保留，和真实链路分别报告。

本地 HTTP 的非授权 Host 401 不等于真实 Cloudflare Access 验收。Wrangler 4.114 的代理在提前拒绝带上传体的跨源请求时，可能出现 `Can't read from request stream after response has been sent` 并退出；新增 HTTP Origin 拒绝探测使用无上传体请求，带 JSON 的拒绝及访问 D1 前阻断由原处理器测试覆盖。没有为此修改业务鉴权、忽略未知字段或升级依赖。
