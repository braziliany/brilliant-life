# Health 同步可靠性

## 唯一成功依据

快捷指令显示成功，只能说明快捷指令完成了自己的调用流程，不能证明 Auto Export Health 当时处于可执行状态，也不能证明网络请求抵达 Pulse。

Pulse 只以 Worker 完成鉴权、解析和每日汇总写入，并成功写下 `health_ingestion_runs` 成功事件作为同步成功依据。

## 页面语义

- 今日存在服务端成功事件：显示这次或今天其他成功 payload 确实包含的指标。
- 今日没有服务端成功事件：显示“今日尚未同步”，步数、能量、锻炼和完成率不显示为 0。
- 成功 payload 明确包含某指标且值为 0：显示 0。
- 成功 payload 没有包含某指标：显示“—”或“暂无记录”。
- “最后同步”来自最近成功事件的服务端 `received_at`，按上海时区显示为 `YYYY-MM-DD HH:mm`。

## 服务端记录

现有 `health_ingestion_runs` 已记录接收时间、精确覆盖日期、指标键、导入天数、状态和来源，因此本轮没有新增 migration。成功来源固定标识为 `Auto Export Health`。

POST 成功响应还会返回数据起止日期、`rowsInserted` 和 `rowsUpdated`。这两个计数用于请求级诊断，不新增持久字段，也不保存原始 Health payload。

## 已知边界

Pulse 不尝试判断或修复 iOS 后台执行机制。当前每日汇总的逐日 upsert 与成功事件写入并非一个显式原子事务；如果 D1 在多日 payload 写入中途发生异常，理论上可能出现部分每日数据已更新但没有成功事件。页面会保守地不把这种情况显示为同步成功，重复发送相同 payload 可继续按日期更新。
