# 当前系统架构

```text
Auto Export Health ─┐
官方工作日历 ───────┤
人工职业经历 ───────┤
Salary Records ─────┤→ 领域层 → API → Data Center / Annual Archive
钱迹导入 ───────────┘                    ├→ Life Insights（只读派生）
                                         └→ Life Timeline（只读派生）
```

## 运行边界

- Cloudflare Workers 承载页面与 API；D1 保存长期事实。
- `pulse.sophier.org/*` 的人类访问由 `Pulse Dashboard` Cloudflare Access Application 与 Owner policy 保护。
- `GET /api/v1/calendar/widget` 使用独立、path-scoped 的 `Pulse Calendar Widget` Application 与 Service Token；该 token 不能进入父级 Pulse 页面或其他私有 API。
- Worker 显式设置 `workers_dev = false`、`preview_urls = false`，canonical workers.dev 与 Version/Preview URL 均不能进入业务处理路径。
- Health 上传继续使用独立 API Key 鉴权，不复用 Dashboard 身份或 Calendar Widget Service Token。
- React 组件负责展示和交互，领域函数负责计算；UI 不重复实现工资、财务、日历、年度或洞察口径。
- Annual 是跨领域只读模型；Life Insights 再从已构建的年度事实派生，不写入 D1。
- Life Timeline 复用 Career、已保存 Salary 与 Annual read model，只生成跨年份只读索引，不创建事件表或时间线快照。
- 全站使用唯一正式顶部导航；首页不再维护第二套领域快捷导航，移动端复用同一组入口的原生展开菜单。

## 数据流

- Health：Auto Export Health → parser/normalizer → `health_daily` 与 ingest 状态 → Health domain。
- Calendar：年度官方配置 + D1 个人覆盖 → Calendar domain。
- Calendar Widget：Calendar domain + 当月 D1 只读查询 → 最小化月度机器 DTO；不写入 D1。
- Career：人工编辑 → `work_experiences` → Career domain。
- Salary：工作日历预计值或明确保存的 `salary_records` → Salary domain。
- Life Finance：钱迹 JSON/XLSX adapter → normalized transaction → `finance_transactions` → Finance domain。
- Annual：按年份与 `asOf` 读取各领域 → Annual domain → 年度页面。
- Insights：Annual/领域结果 → Insights domain → 年度页面说明卡。
- Timeline：Career + saved Salary + Annual read model → Timeline derived model → `/timeline`。

详细边界见[数据与领域边界](./数据与领域边界.md)。
